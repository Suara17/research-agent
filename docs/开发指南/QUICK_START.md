## 🎯 核心改进点

### 1. List & Filter 协议 (负向约束)
- ❌ 旧方法: 搜索 "蛋白质 NOT ADF3" → 失败
- ✅ 新方法: 枚举所有候选 → 逐个验证 → 成功

### 2. 锚点选择算法
- ❌ 旧方法: 搜索第一个约束 → 结果太宽泛
- ✅ 新方法: 特异性评分 → 选最独特的 → 精准

### 3. 强制约束验证
- ❌ 旧方法: 检查1-2个约束 → 不完整
- ✅ 新方法: 所有约束清单 → 全部验证 → 严格

### 4. 多语言搜索
- ❌ 旧方法: 只用英文搜索亚洲话题 → 信息少
- ✅ 新方法: 用中文搜索中国话题 → 信息丰富

### 5. 反确认偏误
- ❌ 旧方法: 找到第一个结果就停 → 著名实体偏误
- ✅ 新方法: 检查3-5个候选 → 避免偏误

## ⚠️ 常见问题

### Q1: 部署后准确率没有提升?
**A:** 检查以下:
1. 提示词是否完整复制(没有截断)?
2. 是否保留了原有的 JSON 格式要求?
3. 测试问题是否属于优化覆盖的类型?
4. 查看日志,确认是否真的使用了新策略

### Q2: 搜索步数增加了?
**A:** 这是正常的。优化后的系统更彻底:
- 负向约束需要枚举+逐个验证(多3-5步)
- 多候选检查(多2-3步)
- 交叉验证(多1-2步)
- **权衡**: 步数+30%,准确率+35% → 值得

### Q3: 某些简单问题反而变慢?
**A:** 调整 planner 的复杂度判断:
- 确保简单问题分配 20 步(不是 30)
- 简单问题不应触发 List & Filter
- 检查模式识别是否正确

### Q4: 如何处理新的失败案例?
**A:** 迭代优化流程:
1. 记录失败案例
2. 分析失败模式(锚点?验证?搜索?)
3. 调整对应提示词部分
4. 重新测试
5. 更新文档
