通过深入分析你提供的日志（`validation_run.md`）和代码文件（`core.py`, `executor.py`, `planner.py` 等），可以确认你的 Agent 在处理复杂多跳问题时确实存在严重的**模块冲突**和**策略失误**。

核心问题在于：**系统设计过于“拥挤”，多个旨在优化的模块（约束分析、死循环检测、侧向突破、动态检索）在互相打架，反而导致 Agent 动作变形，最终在压力下产生幻觉。**

以下是深度复盘分析：

### 一、 核心模块冲突分析 (The "Too Many Bosses" Problem)

你的架构中存在三个主要的“指挥官”，它们发出的指令经常互相矛盾：

#### 1. "宽松的开始" vs "严格的结束" (Constraint Validator vs. Final Verification)

* **现象**：
* 在 **QID 2** 和 **QID 3** 中，`ConstraintValidator` 在第 0 步就判断约束太难，给出了 `feasibility=0.35, strategy=relax`（放宽策略）。
* Agent 接收到的系统提示是：“如果找不到，可以放宽条件”。于是 Agent 找到一个近似答案（如 Arnoldo Mondadori，时间不完全匹配）就觉得可以了。
* **冲突点**：最后的 `Verification` 模块（Reflexion 阶段）却是严格匹配逻辑：“Rejected: 候选答案不符合...”。
* **后果**：Agent 被指示去寻找“差不多”的答案，找到后却因为“不精确”被拒绝，导致陷入死循环或最终强制输出幻觉。



#### 2. "计划执行" vs "执行器自作主张" (Planner vs. Executor Breakouts)

* **现象**：
* `Planner` 生成了一个线性逻辑（Step 1 -> Step 2）。
* `Executor` (在 `web_search` 后) 拥有独立的 `LateralBreakoutManager`（侧向突破）和 `Dead-end Detection`。
* **冲突点**：当 Agent 按照 Plan 搜索（例如搜 QID 4 的“Valorant melee weapon”）时，如果没有直接结果，Executor 判定为 Dead-end，并注入“尝试搜索 X, Y, Z”的提示。
* **后果**：Agent 的注意力被 Executor 的提示分散，偏离了 Planner 的后续步骤（例如去验证 Context 桥接），反而开始在原地打转搜索同义词，直到触发死循环保护。



#### 3. "上下文噪音" vs "锚点聚焦" (Dynamic Retrieval vs. Anchor Logic)

* **现象**：
* 在 **QID 2** 中，Agent 试图确定“那一年”。`web_search` 返回了 1811年彗星、1807年彗星等无关信息。
* `core.py` 中的 `_extract_core_entities` 极其积极地提取实体，并将这些无关年份作为 `Fresh Entities` 注入到 Prompt 中。
* **冲突点**：Prompt 被大量无关实体的 Memory Hits 淹没（Memory Context 变长）。
* **后果**：LLM 丢失了对“锚点约束”（三件事发生在同一年）的聚焦，开始在 1864、1868、1845 之间反复横跳，无法锁定正确的时间轴。

### 二、 具体 Case 失败原因复盘

#### QID 2 (出版商/天文学家/同一年)

* **失败点**：时间轴锁定失败 + 幻觉。
* **过程**：
1. Agent 找到了 1845 (Fizeau/Foucault 太阳照片) 和 1868 (Janssen 彗星/光谱)。
2. 但是 Agent 没能将“不满20岁”和“南欧”与这两个年份做强关联。
3. **致命错误**：因为 max_steps 耗尽，系统触发 `Forcing synthesis`。LLM 被迫在证据不足的情况下“猜”一个答案，于是强行拼接了 `Fratelli Bocca`（太早）和 `Mondadori`（太晚）。


* **根本原因**：**关联搜索能力弱**。Agent 是分别搜“太阳照片”和“彗星”，而没有执行 **Intersection Search（交集搜索）**，例如 `site:wikipedia.org "1868" "comet spectrum" "sunspot"`。

#### QID 3 (海军陆战队/西班牙裔军士长)

* **失败点**：幻觉 + 实体类型错误。
* **过程**：
1. Agent 正确识别了 USMC（1798重建）。
2. Agent 陷入了寻找 "first Hispanic Master Gunnery Sergeant" 的死循环。
3. **死循环**：`core.py` 的 Dead-loop 检测触发了 Level 2 警告，禁止搜索相关词。
4. **强制输出**：系统强制要求 `Final Answer`。由于没有找到真实人名，LLM **编造**了一个名字 "Abigail D. Olmos" 和 "Frankie Segarra"。
5. **验证拒绝**：验证器正确指出这是幻觉，但 Agent 已经没有步数去修正了。


* **根本原因**：**缺乏“无结果”的优雅处理机制**。当搜不到极度冷门的具体人名时，Agent 应该尝试搜索列表（"List of Hispanic Marines"）或向上级概念搜索，而不是在具体 query 上死磕。

#### QID 4 (物理学家/Valorant/刀哥)

* **失败点**：桥接变量（Bridging Variable）丢失。
* **过程**：
1. Agent 找到了 Riot Games 和 Valorant。
2. Agent 卡在了 "Valorant melee weapon" 上。它只找到了 "Tactical Knife"（这是通用名，不是专有名）。
3. **冲突**：Plan 要求找“武器名”，Executor 报 Dead-end。
4. Agent 未能意识到 "Tactical Knife" 可能对应的是 **CS:GO 里的同名武器** 或者 **Valorant 的特殊皮肤名**，也未能联想到“刀哥”可能是中文互联网的俗称。


* **根本原因**：**跨语言/跨文化语境缺失**。问题中提到“刀哥”，这是一个典型的中文社区黑话（可能指《拳皇》或其他游戏角色）。Agent 纯用英文逻辑搜索 "Tactical Knife character" 是搜不到中文梗的。

### 三、 代码级改进建议 (Actionable Fixes)

#### 1. 移除或重构 `ConstraintValidator` 的“预判放松” (Fix Constraint Validator)

不要在搜索开始前就告诉 Agent 可以 `relax`。这会降低 Agent 的求真意志。

* **建议**：完全移除 `feasibility` 预判，或者只在 `step_index > max_steps / 2` 且仍未找到锚点时，才动态注入 Relax 提示。

#### 2. 净化上下文：限制 Dynamic Retrieval (Fix Core.py)

当前的 `_extract_core_entities` 太过激进，导致无关实体污染上下文。

* **修改 `core.py**`：
```python
# 原逻辑：只要是实体就注入
# 新逻辑：只有当实体出现在 Anchor Constraint（锚点约束）的相关上下文中时才注入
if is_entity_relevant_to_anchor(entity, anchor_constraint):
    inject_memory(entity)

```


或者简单地：限制每步只注入 Top 1 最相关的实体，且必须与 Query 有词法重叠。

#### 3. 统一指挥链：Planner 动态更新 (Fix Planner/Executor Interaction)

当 Executor 发现 Dead-end 时，不应只是由 Executor 在 Prompt 里喊话，而应触发 **Re-planning**。

* **建议**：
* 在 `core.py` 中，如果 `meta["dead_end_count"] >= 2`，不要只在 System Prompt 里加提示。
* 直接调用 `planner.py` 的轻量级函数，生成一个新的、侧向的 Search Query，强制覆盖下一步的 Action。



#### 4. 增强“列表优先”策略 (Fix System Prompt)

针对 QID 3 这种找具体人名失败的情况，需要在 System Prompt 中强制一种策略：

* **Prompt 添加**：
> "如果搜索具体实体（如 'First Hispanic MGyS'）失败超过 2 次，**必须**立刻切换为搜索**列表/名录**（如 'List of notable Hispanic Marines' 或 'History of Latinos in USMC timeline'），然后在长文中进行匹配。"



#### 5. 解决 QID 4 的跨语言问题

针对涉及“亚洲巨头”（腾讯）和“角色名”的问题，必须强制跨语言搜索。

* **Prompt 添加**：
> "当涉及亚洲公司（如腾讯、网易）或其代理的游戏时，**必须**尝试构建中文 Query 进行搜索，特别是针对角色昵称或武器俗称（如 'Valorant 近战武器 名字'）。"



### 总结

你的 Agent 不是因为“笨”而失败，而是因为**“想得太多，干扰太多”**。

1. **Constraint Validator** 让它过早放弃精确匹配。
2. **Executor** 的噪音注入干扰了它的注意力。
3. **Dead Loop** 处理机制逼迫它在没有答案时通过幻觉来交差。

**当务之急**：关掉 `ConstraintValidator` 的 Relax 策略，提高 Memory 注入的门槛，并允许 Agent 在找不到答案时输出“未找到”并尝试完全不同的搜索路径（Re-plan），而不是强行合成答案。
