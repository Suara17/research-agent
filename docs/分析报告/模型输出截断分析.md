# Agent模型输出截断问题分析

## 问题概述

在Agent运行过程中，观察到模型输出被截断的现象。这是由于多个因素共同导致的，主要包括API级别的输出长度限制和代码中的显式限制。

## 截断原因分析

### 1. API级别限制 (主要因素)

在 `research_agent/core.py` 文件中，LLM调用设置了 `max_tokens=1024`：

```python
def run_llm_sync():
    return client.chat.completions.create(
        model="qwen3-max",
        messages=prompt_messages,
        tools=tool_schema,
        stream=True,
        temperature=0.4,
        max_tokens=1024  # 这是主要的输出长度限制
    )
```

这意味着模型的单次回复最多只能包含1024个token，超出部分会被截断。

### 2. 其他相关限制

- **上下文窗口限制**：虽然输入+输出的总长度有限制，但主要是输出长度限制导致截断
- **温度参数**：temperature=0.4，模型倾向于生成较保守的输出，但仍可能达到长度限制

### 3. 代码中的其他长度限制

在不同模块中还存在一些其他的长度限制：

- `search.py` 中对内容提取限制为15000字符
- `search.py` 中对PDF内容限制为15000字符  
- `search.py` 中对网页内容限制为15000字符
- 其他模块中也有类似的长度限制

## 影响分析

### 对Agent性能的影响

1. **推理过程不完整**：模型可能在完成推理过程前就被截断
2. **验证表不完整**：约束验证表可能无法完整输出
3. **最终答案不完整**：重要的结论部分可能被截断
4. **工具调用信息丢失**：部分工具调用信息可能丢失

### 对用户体验的影响

1. **信息不完整**：用户无法看到完整的推理过程
2. **答案不完整**：最终答案可能不完整
3. **决策逻辑不清晰**：无法理解模型的完整决策过程

## 解决方案

### 1. 增加max_tokens限制

将 `max_tokens` 从1024增加到更高的值（如2048或4096），但需要注意：

- API提供商的限制
- 成本考虑（token数量影响费用）
- 响应时间可能增加

### 2. 优化提示词结构

- 减少输入部分的长度，为输出预留更多空间
- 优化系统提示词，使其更加简洁高效
- 动态调整提示词长度

### 3. 分段处理策略

- 将复杂的推理任务分解为多个步骤
- 每个步骤专注于特定的子任务
- 避免单次输出过长的内容

### 4. 输出格式优化

- 使用更紧凑的输出格式
- 减少冗余信息的输出
- 优化最终答案的格式

## 推荐解决方案

### 短期解决方案

1. 将 `max_tokens` 从1024增加到2048
2. 优化系统提示词，减少不必要的内容
3. 在输出中优先保证最重要的信息

### 长期解决方案

1. 实现分段推理机制
2. 优化模型调用策略
3. 实现输出摘要功能，对长输出进行自动摘要

## 注意事项

1. 增加max_tokens会增加API调用成本
2. 需要平衡输出质量和响应时间
3. 需要考虑API提供商的速率限制
4. 需要在不同模块间保持长度限制的一致性
