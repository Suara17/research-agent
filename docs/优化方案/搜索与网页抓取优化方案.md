# Agent 搜索与网页抓取优化分析

## 一、当前实现架构

### 1.1 搜索模块 (web_search)

```
查询输入
    ↓
Query 优化 (_optimize_search_query)
    ↓
引擎选择策略:
├── SearXNG (优先)
├── Serper (备选)
├── Baidu (中文)
└── DuckDuckGo (兜底)
    ↓
结果去重与排序 (_deduplicate_and_rank)
    ↓
可选内容增强 (ENABLE_CONTENT_ENHANCEMENT)
```

### 1.2 网页抓取模块 (web_fetch)

```
URL 输入
    ↓
缓存检查 (5分钟有效)
    ↓
域名可达性检查 (智能请求器)
    ↓
4层抓取策略:
├── L1: Trafilatura (最快，静态)
├── L2: curl_cffi (隐身穿透)
├── L3: Drission Session (稳健)
└── L4: Crawl4AI/Drission Browser (重量级)
    ↓
特殊处理:
├── Wikipedia → REST API
├── PDF → 专用解析
└── 失败 → Snippet Fallback
```

## 二、问题分析

### 2.1 搜索模块问题

| 问题 | 现状 | 影响 |
|------|------|------|
| **串行优先策略** | SearXNG 失败才用备选 | 等待时间长 |
| 无结果时无回退 | 单引擎失败无自动切换 | 搜索失败率高 |
| 缺乏查询纠错 | 不检查拼写错误 | 返回无关结果 |
| 多引擎结果未融合 | 各自排序后简单合并 | 可能遗漏好结果 |

### 2.2 网页抓取问题

| 问题 | 现状 | 影响 |
|------|------|------|
| **4层串行尝试** | 一个失败才试下一个 | 最坏情况 10+ 秒 |
| 内容截断过短 | 统一截断 15000-20000 字符 | 长文章信息丢失 |
| 无增量抓取 | 大页面全量抓取 | 浪费带宽 |
| PDF 限制严 | 最多 10 页 | 学术文献可能不全 |
| 缓存策略粗 | 5分钟 TTL，无大小限制 | 内存占用 |

### 2.3 错误处理问题

| 问题 | 现状 | 影响 |
|------|------|------|
| 错误信息冗余 | 大量 print 日志 | 日志噪音 |
| 重试策略固定 | 指数退避但参数固定 | 不适应不同网站 |
| 无降级预案 | 抓取失败无其他方案 | 依赖单一路径 |

#### 方案 3：查询纠错

```python
def correct_query(query: str) -> str:
    """简单拼写纠错"""
    # 检测明显错误
    common_typos = {
        "googel": "google",
        "wikepedia": "wikipedia",
        "youtub": "youtube",
        # 可扩展
    }
    
    words = query.split()
    corrected = []
    for w in words:
        lower = w.lower()
        if lower in common_typos:
            corrected.append(common_typos[lower])
        else:
            corrected.append(w)
    
    return " ".join(corrected)
```

```python
def get_smart_timeout(url: str, attempt: int) -> int:
    """根据域名和尝试次数智能超时"""
    
    domain = extract_domain(url)
    
    # 已知快速域名
    fast_domains = {
        "wikipedia.org": 3,
        "wikidata.org": 3,
        "github.com": 5,
    }
    
    if domain in fast_domains:
        return fast_domains[domain]
    
    # 根据内容类型调整
    if url.endswith(".pdf"):
        return 20  # PDF 下载需要更长时间
        
    # 根据尝试次数递增
    base = 5
    return min(base + attempt * 2, 15)
```

#### 方案 5：并行分层抓取

```python
async def fetch_with_race(url: str) -> str:
    """并行尝试多个抓取方法，最快者胜出"""
    
    # 同时发起所有轻量级请求
    tasks = [
        asyncio.to_thread(trafilatura_fetch, url),
        asyncio.to_thread(curl_cffi_fetch, url),
        asyncio.to_thread(jina_fetch, url),  # 新增 Jina Reader
    ]
    
    # 等待第一个成功者
    done, pending = await asyncio.wait(
        tasks, 
        timeout=8,  # 8秒超时
        return_when=asyncio.FIRST_COMPLETED
    )
    
    # 取消其他任务
    for task in pending:
        task.cancel()
    
    # 返回成功结果
    for task in done:
        try:
            result = task.result()
            if result and len(result) > 100:
                return result
        except:
            pass
    
    # 全部失败，启用重量级
    return await heavy_fetch(url)
```

```python
def smart_truncate(content: str, url: str) -> str:
    """根据内容类型自适应截断"""
    
    # PDF 保留更多
    if url.endswith(".pdf"):
        return content[:25000]
    
    # 百科类保留中等
    if "wikipedia" in url:
        return content[:20000]
    
    # 新闻类保留较多
    if is_news_url(url):
        return content[:18000]
    
    # 默认截断
    return content[:15000]
```
